# Task CRUD API (FastAPI)

A simple CRUD REST API for managing a to-do list, built with **Python** and **FastAPI**.
Data is stored **in memory** (a plain Python list) — no database yet, so all tasks reset
whenever the server restarts. Interactive API docs are auto-generated by FastAPI via Swagger UI.

## Requirements

- Python 3.10+
- `fastapi`
- `uvicorn`

## Setup & run

```bash
# 1. Install dependencies
pip install fastapi uvicorn

# 2. Start the server
python -m uvicorn main:app --reload
```

> **Note (Windows):** if `uvicorn main:app --reload` gives you
> `The term 'uvicorn' is not recognized...`, use `python -m uvicorn main:app --reload`
> instead — this runs uvicorn as a Python module and avoids PATH issues.

The API runs at **http://localhost:8000**.

## Endpoints

| Method | Path         | Description                          |
|--------|--------------|----------------------------------------|
| GET    | `/`            | API info (name, version, endpoints) |
| GET    | `/health`      | Health check                        |
| GET    | `/tasks`       | List all tasks                      |
| GET    | `/tasks/{id}`  | Get a single task by id             |
| POST   | `/tasks`       | Create a new task                   |
| PUT    | `/tasks/{id}`  | Update an existing task             |
| DELETE | `/tasks/{id}`  | Delete a task                       |

### Status codes

| Code | Meaning                                    |
|------|---------------------------------------------|
| 200  | Successful read/update                      |
| 201  | Task created                                |
| 204  | Task deleted (no content)                   |
| 400  | Invalid input (missing/empty title)         |
| 404  | Task with that id doesn't exist             |

## Example request


# Task CRUD API (FastAPI + SQLite) Assignment 2

A CRUD REST API for managing a to-do list, built with **Python** and **FastAPI**.
Data is now stored persistently in a **SQLite** database — tasks survive server
restarts. Interactive API docs are auto-generated by FastAPI via Swagger UI.

This project started as an in-memory list (Assignment 1) and was migrated to
SQLite for this assignment. The API surface — routes, request bodies, response
shapes, status codes — is unchanged. Only the storage layer changed.

## Why SQLite

SQLite was chosen because:

- **Zero setup** — it's a single file on disk, not a separate server process to
  install, configure, or keep running. `sqlite3.connect("tasks.db")` creates
  the database if it doesn't exist yet, with no extra steps.
- **Built into Python** — the `sqlite3` module is part of the standard library,
  so no extra database driver is needed.
- **Perfect fit for this project's scale** — a single-user to-do API with a
  handful of tasks doesn't need the concurrency or networking features of a
  full client-server database like PostgreSQL or MySQL.
- **Easy to inspect** — the whole database is one `.db` file that can be
  opened directly in a GUI tool (DB Browser for SQLite) to see exactly what's
  stored, which made debugging and verifying each stage of this assignment
  straightforward.

If this project needed to scale to multiple concurrent users or run across
multiple servers, the next step would be PostgreSQL — but the code is
structured so that swap is mostly confined to `database_config.py`, since
`main.py` never touches SQL directly.

## Where the database file is stored

The database lives at:

```
tasks.db
```

in the **same folder as `database_config.py`**. The path is built like this:

```python
DB_PATH = Path(__file__).parent / "tasks.db"
```

`Path(__file__).parent` resolves to wherever `database_config.py` actually
lives on disk, so the database is always created next to the code —
regardless of what directory you happen to run `uvicorn` from.

The file is created automatically the first time the app starts. It does not
need to exist beforehand, and it isn't committed to the repository — anyone
who clones this repo and runs the app will get a fresh `tasks.db` generated
for them, seeded with 3 example tasks.

## Requirements

- Python 3.10+
- `fastapi`
- `uvicorn`

(No separate database installation required — SQLite ships with Python.)

## Setup & run

```bash
# 1. Install dependencies
pip install fastapi uvicorn

# 2. Start the server
python -m uvicorn main:app --reload
```

> **Note (Windows):** if `uvicorn main:app --reload` gives you
> `The term 'uvicorn' is not recognized...`, use `python -m uvicorn main:app --reload`
> instead — this runs uvicorn as a Python module and avoids PATH issues.

The API runs at **http://localhost:8000**.

On first run, `tasks.db` is created automatically in the project folder, the
`tasks` table is created, and 3 example tasks are inserted. On every
subsequent run, the existing database and its data are reused — restarting
the server does **not** reset or duplicate the tasks.

## Database schema

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    done  BOOLEAN NOT NULL DEFAULT FALSE
);
```

### Example SQL query

Run directly in DB Browser's **Execute SQL** tab, against the seeded database:

```sql
SELECT * FROM tasks WHERE done = 1;
```

Result:

This confirms the `done` filter works correctly, and — since the API reads
from this same file — refreshing `GET /tasks?done=true` (or filtering
client-side) reflects the exact same result.

## What changed from Assignment 1

| Assignment 1 (in-memory)                  | Assignment 2 (SQLite)                          |
|--------------------------------------------|-------------------------------------------------|
| Tasks stored in a Python list              | Tasks stored in `tasks.db`, a `tasks` table      |
| Data reset on every restart                | Data persists across restarts                    |
| Reads/writes = list operations (`.append`, loops) | Reads/writes = SQL queries (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) |
| `id` assigned via `len(tasks) + 1`         | `id` assigned by SQLite (`AUTOINCREMENT`)        |
| 3 example tasks hardcoded at import time    | 3 example tasks inserted once, only if the table is empty |

The URLs, request bodies, response shapes, and status codes are all
identical to Assignment 1 — only the storage implementation changed.

## Notes

- Data now survives server restarts — this is the main difference from Assignment 1.
- `tasks.db` is excluded from version control (see `.gitignore`) so each clone
  starts with a clean, freshly seeded database.
